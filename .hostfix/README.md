# Pojun 宿主工具修复通道

发布源：`xiaozhu456/pojun-hostfix`；上游：`chu0119/Pojun`。本仓库保留上游许可与历史，修复发布包中的源代码位于对应 `vX.Y.Z-hostfix.N` tag。

本通道修复命令名称、Python 库真实导入、SecLists 字典目录和安装下载格式检测；网页、Agent 和安装助手使用同一套清单。不会伪造命令，也不会把库存固定为全部可用。

## 网页升级

主程序和 root 安装助手都从本仓库获取更新。初次迁移需要同时替换两者；之后继续使用系统配置页的一键更新即可。更新页应显示来源 `xiaozhu456/pojun-hostfix`。安装包和独立安装脚本也固定使用此来源；没有发布物或校验失败时报告错误，不回退上游原包。

版本按 `(上游major, minor, patch, hostfix修复序号)` 比较。普通上游版本的修复序号是0；例如 `0.4.39 < 0.4.39-hostfix.1 < 0.4.39-hostfix.2 < 0.4.40-hostfix.1`。这是本通道的排序规则，不是通用SemVer预发布排序。

手工安装上游原版会绕过此通道并覆盖修复。

## 自动发布

在 Actions 启用 **Hostfix release** 后，每小时第17分钟检查最新上游正式Release，也可手动运行并指定上游tag。同步只接受三段数字正式版，锁定tag对应提交，再严格应用 `series.patch`。发生冲突时停止，不自动生成冲突解决方案。

构建任务只有仓库只读权限，使用临时PostgreSQL和测试配置；完整构建、vet、测试、前端导出及两轮隔离升级验证通过后，才把产物交给独立的发布任务。只有发布任务和每30天维护状态的任务有本仓库写权限。生产服务器不需要GitHub Token。

发布包仅提供Linux amd64，包含 `pojun`、`pojun-hostd`、`pojun-maint`、启动脚本、配置示例、skills和LICENSE，附 `SHA256SUMS` 与 `build-info.json`。发布任务先创建草稿、上传全部资产，再将它设为正式最新版。不覆盖已经存在的tag或Release资产；重试失败构建会使用新的修复序号。

上游没有变化且相同提交/补丁已经完整发布时，不重复发布。旧版本不会盖过新版。公开仓库定时任务存在长期无活动停用机制，因此流水线每30天更新一次状态文件；如Actions被停用，在仓库Actions页重新启用并手动运行即可。

## 维护补丁

控制分支为main。`.hostfix` 和本仓库自己的 `.github/workflows/hostfix.yml` 是受控发布基础，不从上游复制工作流。每份候选源代码都从上游tag重新生成，再应用补丁，因此新版本不会静默丢失修复。

修改修复代码后，重新生成相对选定上游tag的 `series.patch`，包含新增文件和测试，但排除 `.hostfix` 及 `.github/workflows`。运行本地控制器测试，再手动触发发布。`build-info.json` 记录上游提交、补丁SHA256、已验证源代码提交及归档摘要。

```sh
python3 -m unittest discover -s .hostfix -p 'test_*.py' -v
go test ./selfupdate ./hosttools ./hostd
```

发布门禁不跳过失败测试。无法兼容的上游版本不会进入网页升级列表，上一份修复版继续运行；需人工适配后再发布。若上游以后修复相同问题，先去除已冗余的补丁并完成全部验证，再继续同步。

生产部署前保留程序、配置、数据库备份；程序回滚不应自动恢复旧数据库覆盖新数据。GitHub仓库、发布包和CI只能包含公开源代码与测试数据，不能提交主机配置、模型密钥、JWT、SSH凭据或数据库快照。
